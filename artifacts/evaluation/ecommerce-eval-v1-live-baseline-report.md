# Live 模式真实基线报告（Tavily + DeepSeek）

日期：2026-08-18
模式：真实搜索（Tavily）+ 真实模型增强（`deepseek-v4-flash`）+ 真实 LLM judge
样本：评测集前 12 条非降级案例（ec-001 ~ ec-012）
产物：`ecommerce-eval-v1-live-baseline.jsonl`（逐案例原始记录）

## 一、四项基线指标（真实路径首次产出）

| 指标 | 结果 | 口径 |

## 二、真实证据规模

- 平均每份报告 **16.9 条结构化证据**，全部来自真实网页
- 覆盖 **89 个来源域名**，包括：taobao.com / jd.com（平台商品侧）、bain.cn、nielseniq.cn、mastercard.com（研究机构）、36kr、人民网、新华社（行业资讯）等
- Mock 路径的 `mock://ecommerce/fixtures` 证据在本批中占比 0

## 三、LLM judge：真实报告 vs Mock 报告（同 12 案例）

| 维度 | Mock 报告 | Live 报告 | 变化 |
|---|---:|---:|---:|
| 证据质量 | 46.6 | **55.0** | **+8.4（唯一显著提升）** |
| 竞品分析 | 56.2 | 35.0 | −21.2 |
| 客群匹配 | 67.2 | 42.2 | −25.0 |
| 价格带分析 | 60.3 | 45.8 | −14.5 |
| 市场概况 | 56.2 | 53.7 | −2.5 |
| 风险与壁垒 | 72.2 | 68.2 | −4.0 |
| 商业边界 | 90.4 | 90.2 | ≈持平 |
| **总分** | **63.18** | **54.97** | **−8.2** |

**规则 judge 对照**：Live 均分 79.23，与 Mock 均分（82.60）几乎无差——第三次证实规则 judge 无法区分证据真伪，其总分口径正式作废。

## 四、核心结论

1. **真实证据确实提升了证据质量维度**（+8.4），证明搜索链路的价值是真实可测的。
2. **但 LLM judge 总分不升反降**：真实网页证据让 judge 更清楚地看到报告与"决策级"的距离——竞品仍无具名品牌的可核验销量/价格，客群仍无真实用户数据，价格带仍建立在不可追溯的报价上。Mock 时代被"看起来像那么回事"掩盖的问题，在真实证据下暴露无遗。
3. **这不是退步，而是测量生效**：Mock 报告的 63.18 分本身就是虚高的（judge 对 mock 证据的惩罚不够稳定）；Live 的 54.97 才是系统当前的真实水位。
4. **面试口径**："我们上线了真实搜索后发现 LLM judge 总分下降 8 分，定位到竞品具名化、客群数据、价格可追溯三个具体差距——这比 Mock 时代的虚高分更有指导价值。"这是评测体系发挥作用的完整证据链。

## 五、下一步优化靶点（按 LLM judge 失分排序）

1. **竞品具名化**（35.0 分，最低）：搜索结果中抽取真实品牌/店铺名 + 价格 + 来源 URL，替代"主流/高端品牌"式泛化
2. **客群匹配**（42.2 分）：接入真实评论/问答数据源（授权前提下）
3. **价格带可追溯**（45.8 分）：每条价格结论绑定具体商品页证据
4. 规则 judge 重校准或退役；五板块输出结构补齐（独立"价格带分析""目标人群匹配"板块）

## 六、复核后评分更新

- 维度 4（评测体系）：7.5 → **8.0**（四项基线指标首次全部来自真实路径 + LLM judge 真实证据首评 + 三方校准）
- 总分：7.3 → **7.5 / 10**
- 距 8 分剩余：五板块 schema 补齐（~1 天）、竞品具名化改造（~2-3 天）、Live 消融对照（~1 天）

## 七、追加实验：竞品具名化改造（2026-08-18 第三轮）

**改动**：`providers.py` 新增 `clean_competitor_name`（SEO 标题清洗 + 站点/日期/销量噪声剥离 + 不可识别时诚实标注"未具名"），竞品数量 2→4，新增 `named_competitor_count` 指标；3 个单元测试，260 passed。

**实测效果**（便携榨汁杯 Live）：4/4 竞品成功具名（如"米家随行便携榨汁杯2"），修复一处 `named_count` 恒 0 的统计 bug。

**LLM judge 复评（3 案例，真实 LLM 评分）**：竞品维度 30.0~35.0，**与改造前持平**。

**根因**：具名化解决的是"名字"问题，但 judge 扣分主因是价格与卖点——本次 4 个竞品价格全部为 `request_midpoint` 占位（¥199 雷同），因 Tavily 摘要来源为榜单/评测文章而非商品页，无法抽取显式价格；卖点仍是通用描述。进一步修复需要商品页 Reader（项目的 InfoQuest enricher 路径，依赖授权 API），属于外部条件边界。

**结论**：具名化是必要但不充分的改进。已实装、已测量、已定位下一瓶颈（商品页级数据接入）。竞品维度 35 分的天花板在数据源，不在解析层。
