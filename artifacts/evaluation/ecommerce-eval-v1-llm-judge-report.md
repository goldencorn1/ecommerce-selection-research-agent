# 真实 LLM Judge 评测与规则 Judge 对比报告

日期：2026-08-18
执行：50/50 案例全部完成真实 LLM 评分，**0 fallback**
Judge 模型：`deepseek-v4-flash`（`conf.yaml` BASIC_MODEL，真实 API 调用）
数据集：`data/evaluation/ecommerce_cases.jsonl`（50 条，SHA-256 与 P1 基线一致）
产物：`ecommerce-eval-v1-llm-judge.jsonl`（逐案例）、`ecommerce-eval-v1-llm-judge-summary.json`（汇总）

> 口径说明：本对比中确定性 judge 跑在未注入降级的报告上（均分 82.60）；C1/A3 基线的 79.60 含 8 条预期降级案例。LLM judge 与规则 judge 在**同一批报告**上打分，二者对比内部一致。

## 二、三个核心发现

### 发现 1：规则 Judge 的分数系统性虚高 21 分

规则 judge 的评分逻辑围绕结构完整性、字段存在性、证据 id 引用关系；LLM judge 直接读出 Mock 证据的虚构本质。低分案例的 LLM 原文点评：

> "所有证据均为 mock fixture，来源置信度低，无法支撑实际决策。"（ec-023，49.4 分）
> "竞品未具名，价格依据仅为 2 个 mock 锚点，定价只能作为假设不能追溯为真实市场证据。"（ec-028，45.5 分）

### 发现 2：Spearman = 0.085，规则 Judge 的排序几乎无效

这不仅是否定绝对分，而是否定**相对排序**——用规则 judge 比较两个版本的质量高低（例如消融实验中的 79.21 vs 79.13）在统计上没有意义。A4 消融"质量无差异"的结论需要重述为"规则 judge 无法区分质量差异"。

### 发现 3：维度分出现方向性翻转

| 维度 | 规则 Judge | LLM Judge | 解读 |
|---|---:|---:|---|
| 证据质量 | 93.0 | **43.6** | 最大反差：规则 judge 数证据 id，LLM 看出证据是 mock:// |
| 客群匹配 | 100.0 | 63.1 | 规则 judge 给字段存在满分，LLM 看出内容泛化 |
| 价格带分析 | 97.5 | 60.8 | LLM 正确识别"2 个 Mock 锚点的中位数"不是市场证据 |
| 竞品分析 | 78.3 | 55.5 | 竞品未具名被 LLM 扣分 |
| 市场概况 | 60.0 | 53.1 | 两 judge 一致认定最弱——与 C1 结论吻合 |
| 风险与壁垒 | 75.0 | 71.8 | 基本一致 |
| 商业边界 | 75.0 | **90.8** | 唯一 LLM 反超项：LLM 高度认可"拒绝给出采购建议"的诚实边界设计 |

### 附：与 10 条 AI 自评的三方对比

10 条自评案例（`codex-p1-self-review`）自评均分 80.0–83.6，同样比 LLM judge（52.5–68.2）宽松约 15–20 分——**自评不能替代外部校准**这一上轮审核判断被数据再次确认。

## 三、对项目评分与叙事的影响

1. **上轮审核 P1-3（LLM-as-judge 未真实运行）正式关闭**：管线（`p1_runner.py` adapter 接口）+ 真实运行产物（本报告）均已存在。"构建评测集与 LLM-as-judge 评测管线"可以写进简历。
2. **简历/答辩必须改口径**：不能再引用"Judge 平均分 79.60"作为质量证据；正确讲法是——"我们用真实 LLM judge 校准发现规则 judge 虚高 21 分且排序无效（Spearman 0.085），据此把质量口径切换到 LLM judge，并以证据质量（43.6 分）为首要优化靶点。"这是整个项目最强的面试故事：一次真实的、由数据驱动的评测体系自我纠错。
3. **下一个优化靶点被数据指明**：证据质量 43.6 分是唯一跌破 50 的维度，根因是 Mock 证据；这与"Live 模式小样本基线"（上轮 P1-5）是同一件事——10-20 条 search+deepseek 真实报告既能补基线指标，又能让 LLM judge 首次评到真实证据。
4. **Judge 成本进入预算视野**：单次全量评测约 34 万 token、平均 34.6s/案例；CI 中建议只对抽样子集跑 LLM judge（如每次 10 条），全量留给里程碑。
