# 选品研判台：最终产品需求文档

版本：Final V1.0
日期：2026-08-18
产品状态：可运行、可交互、可演示版本已验收
项目类型：个人独立开发项目

## 1. 产品定义

“选品研判台”是一个面向个人卖家和中小商家的电商选品研究 Web 工作台。它把品类假设、研究约束、候选证据、价格锚点、结构化评分、风险边界和下一步验证动作收敛到一次可复跑的研究流程中。

产品输出是“先验证什么”，不是自动宣称爆品，也不是销量、库存、成本或利润事实系统。

## 2. 目标与非目标

### 2.1 产品目标

- 在没有真实商业数据时，仍能用 Mock 完整演示研究流程。
- 让用户看见研究过程、证据边界、评分依据和失败处理。
- 支持用户在页面临时配置自有模型、搜索和商品 API。
- 支持 Excel/CSV 等自有数据输入，并保留字段校验和审计边界。
- 通过历史回放、导出和质量审计支持复核与答辩展示。

### 2.2 非目标

- 不绕过平台访问控制或自动获取未授权商品数据。
- 不把搜索摘要、Mock 样品或模型推断包装成商业事实。
- 不承诺真实销量预测、库存预测、利润核算或采购自动执行。
- 不要求演示环境必须配置真实商业 AI。

## 3. 目标用户与核心场景

| 用户 | 核心任务 | 成功结果 |
|---|---|---|
| 个人卖家 | 判断一个品类先验证哪些方向 | 得到推荐方向、风险和验证动作 |
| 中小商家运营 | 汇总竞品、价格和客群线索 | 得到可回溯的候选证据报告 |
| 产品/采购人员 | 导入自有商品表进行初步筛选 | 完成预览、映射、校验和审计 |
| 评审/答辩人员 | 观察 AI 研究系统的可控性 | 看到 Mock、证据边界、质量门禁和降级状态 |

## 4. V1 功能需求

### FR-01 研究配置

用户可以输入品类、目标市场、客群和价格范围，并选择 Mock 或 Live 模式。默认配置必须支持不填任何外部 Key 直接运行 Mock。

验收标准：默认打开页面后，点击“一键体验 Mock”可以生成报告，外部请求数为 0。

### FR-02 模型与搜索能力配置

页面保留结构化 Mock、DeepSeek、OpenAI-compatible、通义千问、智谱、Kimi、SiliconFlow、Ollama 等模型入口，并保留 Tavily、SearXNG、Brave、Serper 和自定义 HTTP JSON 搜索入口。

用户填写的 Key 只随当前请求使用，不写入 URL、历史报告、SQLite、日志或提交包。

### FR-03 商品 API 配置与 Demo 服务

页面提供：

- 通用 JSON API 模板；
- 本地 Demo 商品 API 模板；
- POST items API 模板；
- 启用/暂停本次商品 API 开关；
- GET/POST、认证方式、响应路径和字段映射配置；
- 预检、样品预览和载入本次研究。

内置接口：`GET /api/ecommerce/demo/product-api?q=折叠桌`。该接口返回固定的 `DEMO_ONLY` 样品，只用于演示，不代表真实商业数据。

验收标准：未启用时预检按钮不可用；启用后预检可读取 3 条样品；样品载入后仍保持 `commercial_decision_ready=false`。

### FR-04 研究编排

V1 采用显式研究链路：

`Supervisor → Market → Competitor → Price → Customer → Risk → Report → Reviewer`

单个模块失败时，系统应保留失败分类、降级状态和其他模块结果，不得伪装成完整成功。

### FR-05 报告内容

报告固定包含五大板块：

1. 需求与趋势；
2. 竞争与价格；
3. 目标客群与需求；
4. 机会与风险；
5. 推荐方向与验证动作。

Web 展示进一步拆分为四个交互区：

`摘要 → 证据 → 风险 → 行动`

每条推荐方向必须包含评分、价格范围、价格依据、证据关联、验证动作、成功阈值、需补数据和失败处理。

### FR-06 图表与信息呈现

报告应显示：

- 推荐方向得分趋势图；
- 价格分布图；
- 研究过程和 Agent 状态；
- 证据边界和质量门禁；
- 运行告警和商业核验提示。

无数据时显示明确空状态，不生成虚假图表。

### FR-07 Excel/CSV 输入

支持 `.xlsx`、`.xlsm`、`.xls`、`.csv`、`.tsv`。流程为：

`上传 → 预览 → 字段映射 → 校验 → 确认导入 → 绑定报告审计快照`

导入内容仍属于用户候选数据，不能自动升级为商业事实。

### FR-08 历史、导出与回放

- 支持 JSON、Markdown、HTML 导出；
- 支持历史报告回放；
- 支持多报告选择和对比；
- 回放不重复调用外部搜索或模型 API；
- 报告保留指纹、Trace ID 和质量门禁状态。

### FR-09 质量与观测

系统区分：

1. 接口成功；
2. 证据可用；
3. 商业决策就绪。

每次研究记录状态、错误分类、耗时、P95 和匿名 Trace ID。50 条评测格式保持固定，人工抽检不得用自动分数冒充人工结论。

## 5. 交互与视觉要求

- 正式页面采用淡蓝色 Commerce Bento 风格；
- 配置、报告、证据和状态卡片保持清晰层级；
- 四段报告导航支持点击定位和键盘访问；
- API 配置在移动端可折叠、可滚动且不产生横向溢出；
- 重要文字与背景保持足够对比度；
- 支持 reduced-motion 场景；
- 运行中、成功、失败、降级和未配置状态必须有清晰反馈。

## 6. 安全与数据边界

- 用户商品 API 只允许安全协议和受控本地 Demo 地址；
- 禁止 URL 内嵌凭据；
- 阻止访问内网、链路本地和保留地址；
- 限制响应体、重定向和 Header 范围；
- API Key 使用 SecretStr 或请求级内存数据；
- 当前匿名 workspace 仅适合本地演示；
- 真实商业化必须由用户提供合法授权、逐 SKU 核验和独立证据。

## 7. 运行与交付要求

推荐运行方式：

```text
双击 start_ecommerce_mock.bat
→ 打开 http://127.0.0.1:3000/ecommerce
```

Docker Compose 验收要求：

- backend 为 `healthy`；
- frontend 返回 HTTP 200；
- `/api/ecommerce/health` 返回 HTTP 200；
- `/api/ecommerce/demo/product-api` 返回 HTTP 200。
