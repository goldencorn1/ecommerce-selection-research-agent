# D1 答辩高频问答与边界口径

更新时间：2026-08-17

## Q1：项目和普通的 AI 选品报告有什么区别？

普通报告往往只给结论。选品研判台把研究拆为市场、竞品、价格、客群和风险五个板块，并为结论绑定证据、置信度、来源类型和下一步验证动作，同时用质量门禁阻止不完整数据直接变成商业决策。

## Q2：没有真实商品数据，项目是否只是演示？

当前提交版本是可运行的 Mock MVP 和真实能力接入框架，不能声称拥有真实商业数据。它仍然具备实际功能：用户可以在 Web 页面配置自己的模型和搜索服务，系统会完成预检、研究编排、报告生成、证据审计、导出和回放；商业数据必须由用户提供合法授权来源。

## Q3：为什么默认使用 Mock？

Mock 是无 Key、可离线、可复现的演示基线，保证评委现场不会因为外部网络或第三方配额导致主流程失效。Live 模式保留兼容接口，适合有合法凭据的使用者接入。

## Q4：DeepSeek 和商品搜索 API 是否可以互相替代？

不能。模型负责结构化报告的语言润色和解释，搜索或商品数据服务负责提供外部证据。项目允许用户自由选择模型，但真实商品数据仍需匹配有权限的搜索、商品页 Reader 或自有数据服务。

## Q5：50 条评测是否证明了真实市场准确率？

不能。50 条评测证明的是 V1 Mock 模式下的 schema、结构完整性、证据覆盖、降级质量和指标计算可重复；它不是销量预测准确率，也不是商业 ROI 证明。真实准确性需要合法数据、跨品类样本和人工业务复核。

## Q6：为什么采用显式八节点，而不是完全动态 Agent？

V1 优先保证可解释、可观测和可回归。显式编排可以让每个研究模块有固定输入输出和独立失败边界。后续可在不破坏协议的前提下增加 Supervisor 动态路由。

## Q7：质量审计中的 blocked 代表系统失败吗？

不一定。blocked 表示商业决策条件不足，是有意设计的安全状态。系统仍可输出候选方向、证据缺口和验证动作，但不会伪造“建议采购”或“建议放量”。

## Q8：项目的商业价值在哪里？

价值在于降低选品早期的信息整理和验证成本，把多个来源的研究结果统一为可追溯报告，并明确下一步需要补齐的证据。生产化阶段再接入平台授权数据、用户业务数据和人工复核流程。

## Q9：如果现场网络或 API 失败怎么办？

按顺序展示能力状态、失败分类、结构化降级报告和离线 Demo。不能临时伪造 Live 成功；Mock 路径是正式演示路径，Live 是可选增强路径。

## Q10：项目下一步最重要的工作是什么？

先完成开发者姓名补录和正式提交材料归档；之后进入 D2，重点推进有合法授权的数据接入、真实搜索质量评测、认证与多用户隔离，而不是继续扩大未经验证的数据承诺。
