## 1. 产品名称与开发背景

### 1.1 产品名称

选品研判台（Ecommerce Research Workbench）。

### 1.2 背景

个人卖家和中小商家在选品时，需要在搜索引擎、电商平台、内容平台和表格之间反复切换，手工整理需求、竞品、价格和风险信息。传统流程存在三类问题：信息分散、来源质量难判断、搜索摘要或模型生成文字容易被误认为真实商业事实。

本产品以“先验证什么”为核心输出，将研究参数、市场趋势、竞品价格、目标客群、机会风险、证据来源、结构化评分和下一步验证动作收敛到一条可复跑链路中。系统在没有合法真实商业数据时使用 Mock 数据完成流程演示，并明确保持商业决策门禁关闭。

### 1.3 产品目标

- 降低从品类假设到验证计划的研究整理成本；
- 让每个推荐方向能回溯到证据、来源和评分依据；
- 区分 Mock、搜索候选证据、用户私有知识和人工商业核验；
- 在外部搜索或模型失败时保留可解释的结构化降级结果；
- 为用户配置合法 API、导入自有数据和后续商业核验预留接口。

### 1.4 目标用户

- 个人电商卖家和独立站运营者；
- 中小商家的选品、采购和市场调研人员；
- 需要快速形成品类验证假设的产品或运营团队；
- 需要演示可追溯 AI 研究流程的课程、训练营或评审场景。

## 2. 用户问题与需求洞察

### 2.1 用户问题

1. 不知道应该先验证需求、价格、竞品还是供应链条件；
2. 搜索结果来源复杂，难以判断地域相关性、发布时间和可信度；
3. AI 报告通常给出结论，却没有明确说明证据、风险和失败处理；
4. 真实商品销量、成本、库存和合规数据通常需要用户自行授权取得；
5. 多次研究结果难以回放、比较和审计。

### 2.2 需求洞察

用户真正需要的不是一个“自动宣称爆品”的工具，而是一份能够回答以下问题的研究工作台：

- 当前有哪些可验证的候选方向？
- 这个方向的证据来自哪里？
- 哪些结论只是模型推断或 Mock 假设？
- 还缺哪些商业数据？
- 下一步用什么小规模实验判断是否继续投入？

## 3. 核心功能需求

### 3.1 研究参数配置

- 输入品类、目标市场、目标客群和价格范围；
- 选择 Mock 离线或 Live 真实搜索模式；
- 选择结构化 Mock、DeepSeek、OpenAI-compatible、通义千问、智谱、Kimi、SiliconFlow 或 Ollama；
- 选择 Tavily、SearXNG、Brave、Serper 或自定义搜索服务；
- 可选配置商品页面 Reader 或导入私有知识文件；
- 支持页面临时 BYOK，Key 不写入报告历史和本地存储。

### 3.2 多 Agent 研究流程

V1 采用显式八节点串行编排：

`Supervisor → Market → Competitor → Price → Customer → Risk → Report → Reviewer`

- Supervisor：校验请求并拆解研究任务；
- Market：整理需求趋势和场景；
- Competitor：提取竞品、定位和价格锚点；
- Price：形成价格假设并标记依据；
- Customer：生成目标客群与需求画像；
- Risk：分析机会、风险和限制；
- Report：合成五大报告板块；
- Reviewer：执行结构、证据和质量门禁检查。

### 3.3 五大报告板块

1. 需求与趋势；
2. 竞争与价格；
3. 目标客群与需求；
4. 机会与风险；
5. 推荐方向与验证动作。

### 3.4 证据与真实性边界

- 每条证据拥有稳定 ID、来源、摘要、置信度和支持结论；
- 证据可区分 Mock、私有知识、搜索候选和未知来源；
- 报告指纹用于回放和核验记录绑定；
- 质量审计区分接口成功、证据可用和商业决策就绪；
- 未经人工核验，不开放直接采购或放量结论。

### 3.5 验证与导出

- 生成验证卡片，包含行动、成功阈值、需补数据和失败处理；
- 支持 JSON、Markdown 和 HTML 导出；
- 支持用户上传 CSV/Excel/TSV 进行预览、字段映射、校验和导入；
- 支持历史报告回放、筛选和对比；
- 支持离线三品类 Demo 材料。

### 3.6 评测与观测

- V1 评测集固定为 50 条 JSONL 案例；
- 支持报告结构、品类相关性、证据覆盖率、评分有效性和降级提示质量等指标；
- 展示成功率、降级通过率、Judge 基线、P50/P95/P99 和人工抽检队列；
- 每次 Web 研究生成匿名 Trace ID；
- 本地观测记录状态、错误分类、平均耗时和 P95。

## 4. 非功能需求

### 4.1 可运行性

- Mock 模式不依赖外部 API；
- Docker Compose 启动后 backend 应达到 healthy，frontend 返回 HTTP 200；
- 提供 Windows 双击快捷启动文件；
- 提供 fallback UI，避免前端构建不可用时完全无法展示。

### 4.2 稳定性

- 搜索和模型调用支持超时、有限重试和模块级降级；
- 支持限流和熔断；
- 单个研究模块失败不能阻塞其他模块报告生成；
- 历史回放不重复调用外部搜索或模型 API。

### 4.3 安全与隐私

- API Key 只在当前请求范围使用；
- 不在响应、报告、日志和提交包中输出密钥；
- 上传文件限制类型、文件名和 10 MB 大小；
- CORS 来源可配置；
- 当前匿名 workspace 只适合本地 Demo，不宣称具备生产级身份认证。

### 4.4 性能指标

当前已验证指标：

- Mock CLI 单次延迟约 13.95 ms；
- Mock 外部请求数为 0；
- Mock 成本为 0；
- 电商相关自动化测试 193 项通过；
- 测试覆盖率审核基线为 62.34%。

未宣称的指标：真实搜索 P95、真实模型成本、商品价格抽取准确率和真实商业决策准确率，需在合法授权数据和稳定网络环境中单独测量。

## 5. 用户交互流程

```text
双击 Mock 启动
  → 进入电商研究页
  → 输入品类、市场和价格范围
  → 选择 Mock/Live、模型和数据源
  → 运行能力预检（Live 可选）
  → 一键体验 Mock / 开始生成报告
  → 查看 Agent 过程与进度
  → 查看推荐、评分、证据和质量审计
  → 查看风险与验证卡片
  → 导出报告或导入商业核验数据
  → 历史回放与多报告比较
```

推荐演示品类为“可折叠露营桌”，正式五分钟路径见 `docs/P3_FINAL_DELIVERY_RUNBOOK_2026-08-17.md`。

## 6. 技术架构与数据流

```text
Next.js Web / fallback UI
          ↓ HTTP JSON
FastAPI 电商 API
          ↓
LangGraph 电商研究图
          ↓
八节点 Agent 串行编排
          ↓
Mock / 搜索适配器 / DeepSeek / 私有知识
          ↓
结构化报告 + 证据 + 质量门禁 + 观测 + 历史
```

主要技术：

- 前端：Next.js、Tailwind、Radix UI；
- 后端：FastAPI、LangGraph、Pydantic；
- 存储：本地 artifacts 和 SQLite 历史；
- 研究能力：Mock、Tavily/兼容搜索、DeepSeek/OpenAI-compatible、私有知识检索；
- 交付：Docker Compose、Mock Compose、Windows 快捷启动文件。

## 9. 当前限制与未来规划

当前项目不自动获取或声称拥有真实平台销量、库存、成本、转化率和 SKU 合规数据。真实数据必须由使用者通过合法授权 API、页面服务或自有文件提供。

后续方向：

1. 补充真实搜索/模型/RAG 的可复现实验；
2. 接入真实 BGE/Rerank 并进行消融评测；
3. 建立人工商业核验结果回流；
4. 增加认证、多用户隔离、密钥管理、任务队列和云部署。
