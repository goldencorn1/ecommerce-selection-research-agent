# 选品研判台：产品设计说明书（P3 交付版）

## 1. 产品定位

“选品研判台”是面向个人卖家和中小商家的电商选品研究工作台。它把品类假设、搜索证据、价格锚点、结构化评分、风险边界和下一步验证动作收敛到一条可复跑流程中。

产品输出的是“先验证什么”的研究结论，不是自动采购、销量预测或库存事实系统。

## 2. 用户问题

用户通常需要在多个平台之间查找需求、竞品和价格，难以判断来源质量，也容易把搜索摘要或 AI 生成文字误认为商业事实。本产品通过证据目录、报告质量门禁和验证卡片降低这种误判。

## 3. 核心流程

```text
输入品类与约束
  → 选择 Mock/Live、模型、搜索源和商品数据源
  → 运行研究模块与状态跟踪
  → 生成五大报告板块
  → 查看推荐、证据、风险和验证动作
  → 导入用户核验数据
  → 历史回放、横向比较和导出
```

## 4. 五大报告板块

1. 需求与趋势：用户需求、场景、痛点和触发因素。
2. 竞争与价格：竞品、价格锚点、价格带和来源依据。
3. 目标客群与需求：客群画像、购买动机和证据关联。
4. 机会与风险：机会、限制、证据不足和合规/商业核验边界。
5. 推荐方向与验证动作：推荐评分、定位、验证动作、成功阈值和失败处理。

## 5. 数据与真实性边界

- Mock 数据：只用于流程演示和自动化回归。
- 搜索摘要：候选证据，不等于商品主数据、销量、库存或利润事实。
- 用户导入数据：显示来源和导入批次，需经过字段校验和商业核验。
- 商品页增强：只使用用户有权调用的 Reader/页面服务，不绕过访问控制。
- 模型推断：只负责归纳、排序和报告表达，不能替代证据。

## 6. 技术实现

- 前端：Next.js、Tailwind、Radix UI。
- 后端：FastAPI、LangGraph 电商研究图、SQLite 本地历史。
- 外部能力：Tavily/兼容搜索源、DeepSeek/OpenAI-compatible 模型、可选商品页增强服务。
- 交付：标准 Compose Live 配置 + 无 Key 的独立 Mock Compose 配置 + dependency-free fallback UI。

## 7. 非功能要求

- Mock 模式无外部依赖即可运行。
- Live、模型和商品页服务必须展示配置/可达/失败状态。
- API Key 只在当前请求范围使用，不写入报告历史或快照。
- 报告保持固定 schema，支持 JSON、Markdown、HTML 导出。
- 外部服务失败时显式降级，不能把降级结果伪装为成功。

## 8. 当前限制与后续方向

当前项目不承诺自动获得平台销量、库存、榜单和成本数据；这些字段必须来自用户有权使用的 API、商品页服务或导入数据。B6 再进行视觉设计和复杂交互收口，后续可继续完善身份认证、云数据库、对象存储和正式商业数据接入。

## 9. P2/P3 交付能力

- 每次研究返回质量审计，区分接口成功、证据可用和商业决策就绪三个门禁。
- 每次 Web 研究生成匿名 Trace ID，并在本地观测中记录状态、错误分类和 P95 延迟。
- Agent 链路、证据边界、阻断原因和质量指标在页面中可回溯展示。
- 提供一键 Mock 启动、固定五分钟演示路径和三品类离线比较材料。
- 提供提交包文件白名单、SHA-256 manifest 和密钥排除检查，确保演示材料可复制且不携带个人授权信息。
