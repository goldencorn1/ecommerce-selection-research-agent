# B6 网页设计调研与候选方案

日期：2026-08-17
范围：GitHub 相似项目网页结构、交互模式、可复用边界与 DeerFlow 电商页面改造方向。

## 一、调研结论

当前项目已经使用 Next.js、React、Tailwind、Radix UI、Lucide、Framer Motion、Sonner 和现有 UI primitives。最稳妥的方案不是替换前端，而是保留现有工程并吸收以下三类模式：

1. Deep Agents UI 的研究过程、设置、调试和运行状态交互；
2. Deep Research Agent 的实时进度、可展开日志、运行/停止、图表和报告下载；
3. Shadcn Dashboard 的响应式工作台、表格、表单、统计卡片和页面布局。

Open WebUI 的多模型、历史、知识库和分析面板值得参考，但其代码包含专有许可证和品牌约束，不作为直接嵌入来源。Perplexica 适合作为搜索首页和来源展示的视觉参考，不作为本项目的完整基座。

## 二、候选项目与可借鉴内容

### 方案来源 A：LangChain Deep Agents UI

仓库：[langchain-ai/deep-agents-ui](https://github.com/langchain-ai/deep-agents-ui)

可借鉴：

- 研究任务连接配置和设置入口；

许可证与风险：仓库页面标注 MIT，但已于 2026-06-28 归档，因此只学习交互结构，不直接复制整套代码或依赖。

## 三、推荐候选设计方向

### 方向 1：研究驾驶舱（推荐）

组合：A + B + C，吸收 D/E 的局部模式。

```text
┌──────────────────────────────────────────────────────┐
│ 顶栏：项目名｜当前任务｜模型状态｜主题｜设置            │
├──────────────┬────────────────────────┬──────────────┤
│ 任务导航       │ 研究主区域              │ 证据/状态侧栏   │
│                │                        │              │
│ 新建研究       │ 结论摘要                │ 模型状态       │
│ 运行中任务     │ 推荐方向卡片            │ 搜索来源       │
│ 历史报告       │ 价格带/评分/风险         │ 任务时间线     │
│ 比较分析       │ 五大报告板块            │ 成本/耗时       │
│ 数据导入       │                        │              │
└──────────────┴────────────────────────┴──────────────┘
```

优点：与当前电商研究任务最匹配，既能展示专业度，又能容纳批量任务、证据和报告。可以直接复用项目现有组件和依赖。

缺点：需要重构当前单页状态组织，B3/B6 需要配合完成。

### 方向 2：搜索发现台

组合：E + B。

- 首页使用大输入框和品类快捷入口；
- 运行后以搜索轨迹、来源卡片和 AI 摘要为主；
- 报告详情再进入五大板块；
- 适合突出“真实搜索”和来源发现。

优点：视觉吸引力强，演示开始阶段容易理解。

缺点：容易退化成通用搜索工具，弱化选品决策、批量比较和结构化报告。

### 方向 3：分析管理台

组合：C + D。

- 首页展示任务数量、成功率、成本、平均耗时和近期报告；
- 主体使用表格、筛选、趋势图和模型对比；
- 适合后续团队、多用户和运营场景。

优点：产品化和管理感强，适合展示 B4 指标。

缺点：第一次演示的故事性较弱，不适合作为唯一首页；需要真实历史数据后才有足够内容。

## 四、推荐决策

本项目建议采用 **方向 1“研究驾驶舱”** 作为主设计，同时吸收：

- 方向 2 的大输入框、来源卡和搜索轨迹；
- 方向 3 的历史、比较、成本和质量指标页。

不建议直接嵌入外部项目。具体实现为“自有页面 + 自有业务组件 + 已验证的交互模式”，这样可以保持当前 API、V1 schema、Docker 和测试体系稳定，并减少许可证和依赖风险。

## 五、B6 实施拆分

### B6.1 设计系统

- 定义颜色：背景、主色、证据色、成功、警告、错误和 Mock 标识色；
- 定义间距、圆角、阴影、字体层级和响应式断点；
- 定义状态徽章、来源标签、质量门禁、风险卡片和按钮状态；
- 添加统一的 motion token 和 `prefers-reduced-motion` 处理。

### B6.2 页面布局

- 新建研究页；
- 任务运行页；
- 报告结果页；
- 历史/回放/比较页；
- 数据导入和模型/搜索预检页。

### B6.3 交互组件

- 研究阶段时间线；
- 可展开证据抽屉；
- 多品类任务表格；
- 模型/搜索能力状态卡；
- 报告板块 Tabs；
- 失败重试和局部失败提示；
- 导出、回放和再次研究按钮。

### B6.4 动画与可用性

- 页面切换 160—240ms；
- 卡片和抽屉使用透明度、位移和高度过渡；
- 进度状态只使用轻量脉冲/进度变化；
- 对用户正在阅读的报告内容不使用自动滚动；
- 支持键盘导航、焦点可见、Esc 关闭抽屉/弹窗；
- 开启减少动画时关闭非必要动效。

### B6.5 测试

- Playwright：新建、提交、切换模式、展开证据、切换报告板块、历史回放、比较、导出；
- 失败路径：模型不可达、搜索失败、批量局部失败、空文件和格式错误；
- 视觉回归：桌面、窄屏、深色主题、长报告；
- 构建与类型检查：Next build、TypeScript、现有全量测试和 Docker 联调。

## 六、当前等待用户选择的内容

请在以下方向中选择网页主风格：

1. **研究驾驶舱**：推荐，适合最终产品和正式演示；
2. **搜索发现台**：更突出实时搜索和来源探索；
3. **分析管理台**：更突出历史、指标、成本和多任务管理。

默认建议：选择方向 1，并在 B6 实施时融合方向 2 的输入与来源设计、方向 3 的历史和指标设计。
