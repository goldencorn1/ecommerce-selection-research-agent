# C0 Demo 交付冻结说明

日期：2026-08-17
适用版本：A0–A5、B1–B6 当前 Demo 版本
目标：冻结一条可重复启动、可重复操作、可重复讲解的 3–5 分钟演示路径。

## 一、推荐启动方式

### 最快捷方式

在项目根目录双击：

```text
start_ecommerce_mock.bat
```

该方式使用独立的 `docker-compose.demo.yml`，不读取项目 `.env`，不需要任何 API Key，启动后打开：

```text
http://127.0.0.1:3000/ecommerce
```

### 服务检查

```powershell
docker compose -f docker-compose.demo.yml ps
Invoke-WebRequest http://127.0.0.1:3000/ecommerce -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:3000/ecommerce/templates -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:8000/api/ecommerce/capabilities -UseBasicParsing
```

预期结果：前端和后端正常运行，backend 为 `healthy`，三个地址均返回 HTTP 200。

## 二、固定主演示路径

推荐示例品类：`可折叠露营桌`
推荐模式：`Mock 演示`
推荐模型：`结构化 Mock`

1. 打开 `/ecommerce`，先说明当前为 Mock 离线演示。
2. 在研究配置中确认品类、市场、中国大陆电商、默认价格区间和 Mock 模式。
3. 点击“开始生成选品报告”，等待运行完成，不重复点击。
4. 展示顶部“当前最值得先验证”区域和研究状态。
5. 展示三条推荐方向、价格范围、评分组成和验证动作。
6. 展开证据与搜索质量，说明候选证据不是销量、库存或利润事实。
7. 展示报告质量门禁和风险边界。
8. 在“历史报告与对比”中打开刚生成的历史报告，说明回放不会重新调用外部 API。
9. 在“研究证据与导出”区域下载 JSON、Markdown 或 HTML 报告。

完整演示耗时目标：3–5 分钟。

## 三、可选增强演示

如果需要展示批量能力，可在批量输入框中输入至少三个品类，例如：

```text
可折叠露营桌
宠物饮水机
桌面收纳架
```

然后展示批量任务的进度、单项状态、完成结果和局部失败边界。批量演示不是 C0 主路径，只有在单品流程稳定后再执行。

如果需要展示 Excel 能力，上传测试文件并只展示列预览、字段映射和核验边界，不把预览内容描述为已验证商业事实。

## 四、固定异常说明

- 未配置真实 API：能力区显示未配置，Mock 仍可运行。
- 真实搜索失败：显示失败原因和降级状态，不伪装成 Live 成功。
- 模型失败：保留结构化报告，报告中显示模型降级告警。
- 批量局部失败：已完成项目保留，失败项目显示原因并提供重试入口。
- Excel 缺少必要字段：显示缺失字段和核验状态，不绕过数据门禁。

## 六、演示边界

Mock 数据用于验证流程，不代表真实市场事实。真实商品信息、销量、库存、排名和利润不能由项目默认生成，必须来自用户有权使用的搜索、商品数据 API 或用户导入数据。DeepSeek 等模型可以负责分析和表达，但不能替代真实商品事实来源。
