# P3 最终演示与交付路径

版本：P3 / 2026-08-17

## 一、交付目标

P3 不再增加未经验证的商业数据能力，而是把已有的 Mock、Live 配置、证据回溯、质量审计、历史回放和离线材料整理成一条稳定、可复现、可评分的演示路径。

## 二、现场 Web 演示（推荐 5 分钟）

### 0:00—0:30：启动与定位

1. 双击项目根目录的 `start_ecommerce_mock.bat`。
2. 打开 `http://127.0.0.1:3000/ecommerce`。
3. 说明：这是无 Key 的 Mock 演示，真实搜索、模型和商品页增强可由使用者自行配置。

### 0:30—1:00：展示配置边界

1. 展示商品品类“可折叠露营桌”、目标市场和价格区间。
2. 展示 Mock/Live 选择、模型预设、搜索服务和商品数据增强配置。
3. 强调 API Key 只随当前请求使用，不写入历史报告。

### 1:00—2:00：一键运行研究

1. 点击“一键体验 Mock”或“开始生成选品报告”。
2. 展示研究进度事件和八个 Agent 状态：任务拆解、市场、竞品、价格、客群、风险、报告、Reviewer。
3. 强调模块失败时会保留降级结果并显示失败原因。

### 2:00—3:30：展示报告可信度

依次展示：

1. 三条推荐方向和评分组成；
2. 研究质量审计：接口成功、证据可用、商业决策就绪；
3. 阻断原因和 Trace ID；
4. 证据边界审计、来源类型、置信度和支持结论；
5. 展开一条证据详情，说明候选证据不等于销量、成本、库存或合规事实。

### 3:30—4:20：展示评测和导出

1. 展示 50 条评测基线、成功率、降级通过率、Judge 均分和 P95。
2. 展示本地观测运行数和 P95。
3. 下载 JSON、Markdown 或 HTML 报告。

### 4:20—5:00：展示业务闭环

1. 回到历史报告，展示回放和对比。
2. 打开离线比较材料 `artifacts/p3/demo/index.html`。
3. 展示 `commercial-verification-demo-only.jsonl` 与 `blocked` 预检。
4. 收束表述：系统给出“先验证什么”，不在缺少合法商业数据时直接给出采购或放量结论。

## 三、离线材料演示

执行：

```powershell
.\.venv\Scripts\python.exe main.py `
  --ecommerce-demo `
  --ecommerce-demo-dir artifacts/p3/demo `
  --ecommerce-demo-categories "可折叠露营桌,便携榨汁杯,桌面收纳盒"
```

然后打开 `artifacts/p3/demo/index.html`。该材料不依赖 API，不发起外部请求，并保留 `DEMO_ONLY` 商业核验边界。

## 四、异常演示口径

| 场景 | 应展示什么 | 正确表述 |
| --- | --- | --- |
| Mock | 稳定报告和完整流程 | 离线演示数据，不是市场事实 |
| 搜索 Key 缺失 | 能力状态与配置提示 | 用户配置合法搜索 API 后启用 |
| 模型网络失败 | 降级状态和错误分类 | 结构化报告仍可保留，模型润色未完成 |
| 商品 Reader 未配置 | 商品数据增强未配置 | 页面增强不等于销量/库存 API |
| 商业核验未完成 | quality audit 阻断 | 不能直接采购或放量 |

## 五、现场验收标准

- 启动后 backend 为 `healthy`，frontend HTTP 200；
- Mock 研究返回 3 条推荐方向；
- Agent、证据、质量审计、评测基线均可见；
- 至少一条证据可展开查看来源边界；
- 可导出 JSON/Markdown/HTML；
- 离线材料可打开；
- 提交包不包含 `.env`、API Key、OAuth Token 或个人配置。

## 六、不可承诺事项

不要将 Mock、搜索摘要、模型生成文字或未核验商品页描述成真实销量、库存、供应商成本、转化率或合规事实。真实数据必须由使用者提供合法授权来源后导入。
